## 三个值得说的做法

**1. 契约先行,一份配置双产物。**
每门课是一份 JSON 契约:单元格数据、分步指南、公式参数、验收断言全在里面。生成器据此长出交互动画课,出片器据此生成录制计划——文字、画面、配音同源,天然同步。公式**真算真回读**(HyperFormula/引擎实算,验收比对公式原文),杜绝手写假结果。

**2. 探针实证,绝不猜接口。**
OnlyOffice 的建表 API、LibreOffice 的图表插入、GSAP 的确定性边界——每一处未知先写探针跑真实环境,拿到证据再动手。最典型:抓窗式出片用双图对照截帧实证了 `BarDiagram.Vertical` 的语义是 **True→横条**(与直觉相反),据此定下"图型按菜单文本分派"的规则。本阶段所有"实现按文档编写"的猜测,最终都被实测修正过至少一轮。

**3. 闸门式计划,先立验收再铺量。**
L2 复合课 Sprint 按"1 门端到端闸门 → 批量"推进;介绍视频按"机器判空 + 抽帧目检"验收。阶段目标全部带可复现证据(命令输出、回归数字、截图),完成定义不含"感觉差不多"。
