# 拥有你自己的 Daily · 3/4 · 马上看到效果

写东西最怕的不是写不出，是**改了不知道长什么样**。这一篇给你两条
"马上看到"的路：

| | 本地预览 | 线上网址 |
|---|---------|---------|
| 速度 | 改动**立刻**生效 | 推送后等 1–2 分钟 |
| 需要什么 | 你的电脑跑一条命令 | 什么都不用，等就行 |
| 适合 | 写作时反复改 | 发出去前的最终确认 |

## 本地预览：改一行，立刻变

对 AI 编程助手说：

```text
在我的 daily 仓库里启动本地预览，起好后告诉我地址。
```

它会跑一条命令（背后是 `pnpm dev`，你不用记），然后给你一个地址——
浏览器打开 `http://localhost:4016`，你的站就在眼前了。

**这时候去改一篇文章保存**（或让它改），浏览器页面会自己刷新——
不用任何操作，这就是"马上看到效果"。

> **如果你自己动手而不是让 Agent 代劳：** 终端里按 `Ctrl-C` 停止预览。
> 端口被占用起不来时，说明已经有一个预览在跑，直接开浏览器访问即可。

三个地址值得收藏（都在 `http://localhost:4016` 下，`#` 后面是页面名）：

- `/#/` —— 首页卡片墙
- `/#/writing` —— 写作台（左边目录、右边实时预览）
- `/#/collections` —— 收藏的作品墙

## 线上验收：等一两分钟

推送之后，两条路确认"网站已经更新"：

1. **看构建**：仓库 **Actions** 标签页，最新一次运行变绿 ✓；
2. **看实物**：打开你的正式网址，**强制刷新**（Mac 按 `Cmd+Shift+R`，
   Windows 按 `Ctrl+F5`），看到新内容。

优先看构建再看网页——网页没更新多半只是浏览器缓存，强刷就能解决。

## "我改了为什么没生效"对照表

| 现象 | 多半是 | 怎么办 |
|------|--------|--------|
| 本地页面一直转圈 | 预览没起来 | 看终端有没有报错，把报错原样发给 Agent |
| 本地起了但没新内容 | 改的文件和看的不是同一个 | 让 Agent 确认文件路径和访问的地址对不对 |
| 线上没有新内容 | 构建还在跑，或浏览器缓存 | 先看 Actions 是否变绿，绿了再强刷 |
| 文章根本没出现 | 忘了 `status: published` | 检查文章开头身份证里那一行 |
