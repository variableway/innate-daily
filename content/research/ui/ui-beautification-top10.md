## 问题定义

当前站点基于 `base-vega` 极简白风格，存在两个可感知的问题：

1. **UI 生硬，线框不够柔和**：大量 1px 硬边框（`--border: oklch(0.94 0 0)`）+ 偏小圆角（上游 `--radius: 0.625rem`），卡片、按钮、输入框都是「线框感」，缺少层次和呼吸感。
2. **配色过于单调**：浅色面全部提亮到接近纯白（oklch 1.0 / 0.99 / 0.985），中性色无 hue（纯灰），全站唯一的色彩来源是标签 badge 和 mermaid 图。

好消息是：本站颜色全部走语义 token，且 `@innate/ui` 已内置 **5 个主题变体**（`linear` / `notion` / `shadcn-default` / `shadcn-studio` / `webshell`），大部分优化可以只在 `src/globals.css` 的覆盖层完成，不动组件代码。

## Top 10 方案

### 1. 切换内置 Linear 主题 ⭐ 成本最低

`@innate/ui` 自带 `linear.css`，Linear 风格以柔和阴影分层替代硬边框、深色侧边栏、微圆角著称，正好对治「生硬」。

- **实现**：`ThemeSelector` 已是现成组件，切换 `data-theme="linear"` 即可；或在 `globals.css` 默认加载该主题。
- **好处**：零开发量；token 映射完整（明暗两套）；工程感、现代感强。
- **坏处**：风格偏「开发者工具」，深色侧栏与个人笔记的轻盈感略有出入。

### 2. 切换内置 Notion 主题 ⭐ 最契合笔记定位

`notion.css` 是暖纸色背景 + 无框化布局，笔记产品的经典视觉。

- **实现**：同上，一行主题切换。
- **好处**：暖色调立刻解决「单调冷白」；无框设计天然柔和；与个人 blog 气质最匹配。
- **坏处**：暖纸色在部分显示器上显脏；与现有「提亮纯白」覆盖冲突，需清理 `src/globals.css` 里的 `:root` 覆盖。

### 3. Token 级微调：大圆角 + 软边框

不换主题，只修两个变量：

```css
:root {
  --radius: 0.875rem; /* 0.625 → 0.875，所有组件圆角联动变大 */
  --border: oklch(0.955 0 0); /* 边框再淡一档，存在感降低 */
}
```

- **好处**：一行改动全站生效（token 体系的最大红利）；风险极小、可快速 A/B。
- **坏处**：只治标，配色单调问题没解决；圆角过大可能让按钮显得「卡通」。

### 4. 去边框化：用阴影和底色分层（Borderless）

Linear / Stripe 式做法：卡片去掉 1px border，改用「底色对比 + 多层柔和阴影」区分层级：

```css
.card-soft {
  border: none;
  box-shadow:
    0 1px 2px oklch(0 0 0 / 0.04),
    0 4px 12px oklch(0 0 0 / 0.05);
}
```

- **好处**：高级感提升最明显的一步；视觉噪音大幅下降。
- **坏处**：纯白背景上阴影分层需要底色配合（背景必须比卡片暗一点）；暗色模式下阴影几乎失效，需改用边框或发光。

### 5. 暖调中性色：给灰色加一点点 hue

把纯灰（chroma = 0）换成带微弱 hue 的 oklch 灰，如暖灰 `oklch(0.97 0.005 80)` 或冷灰 `oklch(0.97 0.008 250)`：

- **好处**：「单调感」立刻消失，页面有温度；改动仍集中在 token 层。
- **坏处**：全站 hue 必须统一（暖到底或冷到底），混搭会显脏；需逐项验证对比度。

### 6. 编辑色板：分类固定强调色

现状标签 hue 由名字 hash 随机生成。改为 8–12 色策划色板（pastel 系），分类与颜色固定映射：

| 分类     | 建议色                    |
| -------- | ------------------------- |
| insight  | 蓝 `oklch(0.58 0.12 250)` |
| research | 紫 `oklch(0.58 0.12 300)` |
| demo     | 绿 `oklch(0.58 0.12 150)` |
| weekly   | 橙 `oklch(0.62 0.12 60)`  |

- **好处**：全站有了稳定的「色彩记忆点」；信息识别效率提升（看到紫色就知道是研究笔记）。
- **坏处**：新增分类需人工配色；低彩度 pastel 在白色背景上做文字色时对比度需逐个验。

### 7. 彩色表面：侧栏与导航用淡彩底色

侧栏、列表选中态不再用灰，改用「当前强调色的 6–10% 稀释底」（现有 label-chip 已在用 `color-mix` 技法，直接推广）：

```css
.sidebar {
  background: color-mix(in oklab, var(--accent-hue) 4%, white);
}
```

- **好处**：色彩面积从「点」（badge）扩大到「面」，单调感根治；色彩仍受控不刺眼。
- **坏处**：多色面并存时需统一明度/彩度（沿用 `--label-l / --label-c` 机制）；过度使用会像「幼儿园配色」。

### 8. Glassmorphism 点缀：浮动元素毛玻璃

顶栏、浮动 TOC、移动端抽屉加 `backdrop-filter: blur(12px)` + 半透明白：

- **好处**：滚动时内容透过毛玻璃，层次感和精致感立刻提升；实现只需少量 CSS。
- **坏处**：`backdrop-filter` 有性能成本（低端机掉帧）；大面积使用会显得廉价——只给浮动层。

### 9. 渐变强调：Hero 与标题点睛

`landing` 页大标题、链接 hover、选中态下划线使用 2 色渐变（如蓝→紫），配合 `background-clip: text`：

- **好处**：一个渐变就能成为全站品牌记忆点；适合 landing 这种唯一展示位。
- **坏处**：与个人笔记的克制气质有冲突风险；正文区禁用，只用于 landing / 空状态插画。

### 10. 引入社区主题生态（tweakcn / shadcn 主题市场）

shadcn 生态有成熟的可视化主题编辑器（tweakcn 等），可实时预览并导出 token CSS，直接贴进 `globals.css` 或沉淀为 `@innate/ui` 的新主题变体。

- **好处**：可视化试错成本最低，一次导出全套明暗 token；可参考数百个现成搭配。
- **坏处**：导出 token 与 `@innate/ui` 的 D0 变量名需逐一核对；主题变体多了之后维护成本上升（建议最终只保留 2–3 个）。

## 推荐组合（落地方案）

按「成本 × 收益」推荐三步走，全部只动 `src/globals.css` 与主题切换，不改组件：

| 步骤              | 组合                                                   | 预期效果                       | 状态 |
| ----------------- | ------------------------------------------------------ | ------------------------------ | ---- |
| 第一步（10 分钟） | 方案 2 或 1：直接切 `notion` / `linear` 主题           | 生硬感消失大半，立刻可对比     | ✅ 已落地（2026-10-13）：首访默认 `notion`，侧栏头部接入 `ThemeSelector`（11 个变体 + 明暗/跟随系统） |
| 第二步（半天）    | 方案 3 + 5：圆角 0.875rem、边框淡化、中性色加 hue      | 在选定主题上做「本站专属」微调 | ✅ 部分落地：全局 `--radius` 提升至 0.75rem；提亮覆盖限定 default 主题（此前会压平所有变体底色）；中性色加 hue 待评估 |
| 第三步（1–2 天）  | 方案 6 + 7 + 4：固定色板、彩色选中态、卡片去边框改阴影 | 形成完整视觉语言，配色单调根治 | 待实施 |

方案 8/9/10 作为后续增强，不进第一版。

## 验证清单

- [ ] 暗色模式下逐项检查：边框可见度、阴影失效后的层级、label-chip 对比度（WCAG AA ≥ 4.5:1）
- [ ] mermaid hex token 与新主题协调（现状蓝紫系，暖主题下需换暖色系）
- [ ] 移动端抽屉 / Sheet 的毛玻璃性能
- [ ] `pnpm --filter @innate/ui` 侧若新增主题变体，遵守「token 唯一来源」纪律，不在 app 层写 raw hex（mermaid 除外）
