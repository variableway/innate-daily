# 写作与发文（daily 站）

## 规范来源：先读再写

动手前**完整读一遍 `docs/basic/markdown-usage.md`**——那是本站的
写作规范（frontmatter 字段、目录即分类、图片规则），以它为准。
这个文件更新后，你的行为自动跟着更新，不需要改这个 skill。

## 硬规矩

1. 文章落进 `docs/` 对应目录，目录即栏目（`docs/use-cases/`、
   `docs/basic/`……新栏目 = 新文件夹）；
2. frontmatter 必填：`title`、`slug`、`date`、`author`、`status`；
   没有发布意图就写 `status: draft`，用户说"发布"才改 `published`；
3. 插图一律用**可访问的外链 URL**，本地路径在站点上会挂；
4. 改完起本地预览让用户确认，再谈发布。

## 写作风格指引（本站的"腔调"）

- **从人话开始，不从概念开始**：第一段讲读者会得到什么，
  不罗列名词；
- **每屏最多一个新概念**，出现立刻配一个生活类比
  （如 `go.mod` 像购物小票）；
- **代码是风景不是教材**：代码块尽量短，配一句"这是什么"的旁白，
  不逐行讲解；
- **写翻车点**：真实报错长什么样、只读最后一行、修复用的一句话；
- **给验收时刻**：读者要做到什么动作、看到什么才算成功，
  越具体越好（"手机浏览器打开正式网址"）。

## 这个 skill 可以整个换掉

上面"写作风格指引"一节只是**本仓库当前的偏好**，不是标准。
不喜欢这个腔调：直接改这个 SKILL.md，或整个换成你自己的写作风格
文件——硬规矩一节建议保留，它对应站点解析器的真实约束。
